01 · The engineering problem

Speed moves the bottleneck
to the decision.

An agent can write the change and its confident summary. Acceptance needs an independent basis: what was allowed, what actually ran, and which code the result belongs to.

01 / AUTHORITY

Who may change what?

A versioned role policy is recorded at launch. MCP authorization binds workers to their own tasks; scope checks constrain candidate changes.

Cost: policy maintenance + credential lifecycle
02 / VERIFICATION

Did these checks run here?

The daemon runs frozen commands on a disposable snapshot. Required reports must contain executed tests. A later source change invalidates acceptance.

Cost: snapshot + actual check runtime
03 / CONTINUITY

Why does this code exist?

Source links connect a symbol to rationale, decisions and a persisted plan. Supporting evidence carries the identity of the source it tested.

Cost: authored links + meaningful assertions
02 · The control plane

Agents propose.
The gate measures.

One Spring Boot application. Durable state in PostgreSQL. Separate task worktrees. A distinct integration candidate.

Enforced through the control planeTask ownership, recorded role policy, frozen checks, path scope and source fingerprints constrain the supported workflow.

Trusted outside this boundaryThe local OS user and daemon. Git worktrees are not process sandboxes. A hostile same-user shell needs a stronger execution boundary.

A symbol carries its why.
Evidence carries its when.

05 · Engineering choices

Make the failure modes
part of the design.

EXECUTION

Freeze, then measure.

Commands and required report scopes are immutable before launch. Verification runs on a disposable copy, clears old reports and rechecks source integrity.

Missing, empty or skipped-only required reports refuse.
RECOVERY

Intent outlives a thread.

Authored plan revisions and the execution ledger persist in PostgreSQL. Resume recovers intent and outstanding work without treating a declaration as completion.

Database state is durable; process recovery still has limits.
PARALLELISM

Independent candidates.

Matched workers use a common baseline and separate worktrees. Model tiers and fresh quotas constrain admission. Parent review chooses files for a verified integration.

Duplicate execution costs quota; agreement is not proof.
How do OpenRewrite recipes fit?

Recipes supply scoped Java analysis and mechanical transformations. Discovery and inspection precede execution; a patch is previewed before application. Applying a patch is not acceptance: source identity, allowed paths and the frozen verification gate still apply. Optional providers require explicit provisioning; this page does not claim vendor parity.

Why Java, PostgreSQL and MCP?

Java keeps the core, compiler parsing and Java tooling in one runtime. PostgreSQL supplies transactions and durable identities for plans, launches and evidence. MCP lets Claude and Codex use the same control surface. One local service keeps operational complexity manageable while the boundaries are being tested.

What prevents stale evidence after a source change?

Verification records a source fingerprint, and completion checks it again. The recorded semantic query reports its evidence status separately. A verifier result for another tree cannot establish current completion evidence. Fingerprints provide identity, not semantic understanding.

Can an agent still weaken tests or bypass the daemon?

A frozen command does not make agent-editable test code or build scripts trustworthy. Test-integrity review and externally owned acceptance assets are still necessary. A hostile process with the same OS-user privileges is outside this local prototype's enforcement boundary. Production requires separate identities, protected control configuration and isolated execution.

Do the docs replace Markdown or provide a full LSP?

No. Stable source links and an authored plan are the structured foundation. Existing Markdown can remain useful narrative and can be migrated selectively. The current parser has partial Java syntax coverage without full attribution. MCP assembles the semantic explanation; a general enriched LSP and automatic truth checking of arbitrary prose are further work.

07 · The honest boundary

Confidence should be
as specific as the evidence.

Implemented mechanism

Source-bound acceptance

Frozen checks, required executed reports, independent candidate verification, durable plan context and task-bound access.

Trust assumption

A trusted workstation

The local user and daemon are trusted. Worktrees are not an OS sandbox; database records are not an externally tamper-proof audit store.

Deployment boundary

Operator-owned deployment

The local operator controls the host and release switch. The recorded scenario evaluates task acceptance within that trust model.

Development method: agents implement bounded changes; the parent reviews differences; the daemon measures configured checks. Self-hosting does not certify the system that performs the checks.

The operating principle

Make evidence specific.
Make refusal cheap.

Give the team fast feedback and a clear route to a safe release. Give the person responsible for that release an understandable basis for the decision.
